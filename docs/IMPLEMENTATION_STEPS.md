# 단계별 구현 계획

장면마다 원본 가이드 한 장을 지정한다. 편집 시트의 각 행과 각 반복은 그 가이드와 한글 지시로 독립적인 PNG 한 장을 만든다. 예를 들어 전선이 가려진 낮 거실 한 장에서 빨간 전선, 물결 모양 전선, 바닥 재질 변경, 야간 조명을 따로 만든다. 필요한 배치·가림·카메라 시점은 가이드에서 갖춘다. [엑셀 형식과 CLI 사용 예시](../README.md#정식-cli-사용-예시)

1단계의 GPU 실행과 2단계의 색·형태 실험까지 진행했다. 다음 품질 실험은 같은 가이드로 주변 환경과 낮·밤을 각각 바꾸는 것이다. GPU 없이 개발할 수 있는 3~5단계와 실제 추론을 결합하는 6단계를 구분한다.

## 1. 가이드 한 장에서 빈 바닥 A 만들기

**완료.** 로컬 모델 `models/FLUX.2-klein-4B/`와 로봇청소기 시점을 본뜬 합성 가이드 `pilot/guides/living01.png`를 사용했다. `scripts/pilot_a.py`로 노란 양말을 지웠고, 같은 조건에서 두 번 생성한 PNG의 해시가 일치했다. [입력과 결과 비교](images/pilot-a-comparison.webp)

RTX 5060 Laptop GPU 8GB에서 로컬 Diffusers로 한글 지시 한 건을 실행한다. EXIF 방향을 적용하고 가이드의 화면비를 유지한다. 초기값은 4스텝과 `guidance_scale=1.0`이다. 메모리가 부족하면 CPU 오프로딩이나 화면비를 유지한 해상도 조정으로 다시 측정한다.

**완료 기준**은 `A.png`에서 장애물이 사라지고 원래의 낮은 시점, 줄눈, 책상 다리 위치가 유지되는 것이다. 성공한 실행의 입력·출력 크기, GPU와 총 VRAM, PyTorch·CUDA·Diffusers 버전, 정밀도, 오프로딩 방식, 최대 GPU 메모리(측정 지표와 MiB)를 남긴다. 모델 적재 시간과 한 장 생성 시간(추론 시작부터 PNG 저장까지)은 따로 잰다.

## 2. 같은 가이드에서 편집 종류별 품질 확인하기

전선의 가운데가 나무 다리 뒤에 가려지고 양끝이 보이는 `pilot/guides/living01_cable_behind.png`를 공통 가이드로 사용한다. 비교할 때는 각 지시를 원본 한 장에 따로 적용하고 시드·해상도·모델 설정을 맞춘다. [실측 사진과 재현 명령](../README.md#이미-가려진-전선의-색과-모양-바꾸기)

| 변형 | 현재 상태 | 원본과 대조할 부분 |
|---|---|---|
| 전선 색 | 예제에서 확인 | 다리 양옆의 피복이 모두 빨개졌고 두 단자와 가운데 가림이 유지됐다. |
| 전선 형태 | 부분 확인 | 고리와 물결은 생겼다. 고리의 굵기, 굴곡 수, 지정한 쪽만 바뀌었는지는 결과마다 확인한다. |
| 주변 환경 | 다음 실험 | 타일을 나무 마루로 바꾼다. 전선·단자·책상 위치와 카메라 시점을 대조한다. |
| 낮·밤과 조명 | 다음 실험 | 낮 거실을 밤으로 바꾼다. 창밖의 밝기와 실내등이 함께 바뀌고 전선과 가림이 식별되는지 확인한다. |

**완료 기준**은 네 지시의 결과를 각각 공통 가이드 옆에 놓고, 원하는 변화와 벗어난 부분을 판정해 기록하는 것이다. 입력 지문, 시드, 모델 처리·저장 크기, 장당 시간과 최대 GPU 메모리를 남긴다. 초기 A → B → C 실험에서는 기존 전선을 다리 뒤로 옮기는 요청이 두 조건 모두 미통과였다. [초기 파일럿 기록](../README.md#초기-파일럿-기록)

## 3. 사람이 작성한 엑셀 읽기

원본 엑셀을 읽기 전용으로 연다. `장면` 시트의 필수 열은 `장면 ID`, `가이드 사진`이다. 공간·가구, 바닥·이음새, 조명은 선택적인 원본 설명이다. `편집` 시트의 필수 열은 `편집 ID`, `편집 지시`다. 모든 편집 행을 각 장면에 적용하고, JPG·PNG 가이드 경로는 엑셀 폴더를 기준으로 해석한다.

**완료 기준**은 임의의 편집 ID로 슬리퍼 색만 바꾸는 한 행짜리 요청과 같은 가이드에 여러 지시가 있는 파일을 모두 읽는 것이다. 중복 ID, 필수 셀 누락, 읽을 수 없는 사진은 시트·행·열과 값으로 찾을 수 있어야 한다. 엑셀 자체가 없으면 찾던 경로와 필요한 두 시트를 안내한다.

## 4. `vgen prepare`로 독립적인 작업 계획 저장하기

`pyproject.toml`에 프로젝트의 직접 의존성과 `vgen` 진입점을 선언한다. 기본 설치에는 `prepare`에 필요한 엑셀·이미지 처리 패키지를 넣고, PyTorch·Diffusers 등 GPU 추론 패키지는 선택 설치로 둔다.

장면 × 반복 × 편집 행으로 작업을 펼친다. 각 작업의 가이드 경로·SHA-256, 최종 한글 지시, 시드, 출력 경로를 `plan.json`에 저장하고 모델 경로와 생성 설정도 기록한다. 작업별 시드는 기준 시드와 장면 ID·반복 번호·편집 ID로 정한다. 최종 지시를 조합할 때 사용자가 변경하려는 속성에는 해당 편집 행의 지시를 우선한다.

**완료 기준**은 GPU와 가중치 없이 1개 장면 × 4개 편집 × 1회에서 4개 작업, 2개 장면 × 3개 편집 × 2회에서 12개 작업을 계획하는 것이다. 편집 행을 뒤섞어도 같은 ID의 가이드·시드·출력 경로가 같아야 한다. 사진 한 장으로 네 변형을 만들 때 네 입력의 지문이 모두 원본과 일치해야 한다. 생성 전 다시 준비할 때는 검사를 통과한 계획만 한 번에 교체한다.

## 5. 저장된 계획의 실행과 파일 기록 검증하기

테스트용 생성기로 `plan.json`의 작업을 실행한다. 추론 전 가이드의 지문을 대조한다. PNG는 임시 파일에서 최종 위치로 옮긴 뒤 `manifest.jsonl`에 작업 ID, 성공·실패, 입력 가이드와 출력의 경로·지문을 기록한다.

**완료 기준**은 엑셀을 수정한 뒤에도 저장된 프롬프트·시드·가이드 경로로 실행되는 것이다. 준비 후 가이드가 바뀌면 해당 가이드를 쓰는 추론 전에 경로를 알린다. `wave` 추론 한 건의 실패를 재현해도 같은 가이드의 `floor`, `night` 및 다른 장면 작업이 원본에서 계속 생성돼야 한다.

## 6. `vgen generate`로 실제 PNG 생성하기

파일럿에서 확인한 로컬 모델 적재·EXIF 처리·화면비 보존·단일 이미지 추론 코드를 `vgen` 패키지로 옮겨 5단계의 실행기에 연결한다. 실행당 한 번 로컬 파이프라인을 적재하고 매 작업에 계획이 가리키는 원본 가이드 한 장을 전달한다. 파일럿 전용 파일은 9단계에서 정리한다.

첫 추론 전 `run.json`에 계획 지문, 사용한 버전, 가중치·토크나이저·설정 파일의 상대 경로와 SHA-256을 기록한다. **완료 기준**은 2단계의 독립 편집들을 정식 CLI로 실행해 계획에 적힌 PNG들을 저장하고, 각 작업의 입력 지문과 결과를 같은 가이드의 파일럿과 대조하는 것이다. 미준비 폴더는 모델 적재 전에 `prepare`를 안내하고, 생성을 시작하면 계획을 고정한다.

## 7. `vgen resume`으로 남은 작업 이어가기

계획 지문, 작업별 성공 기록, PNG의 상태와 지문을 대조해 남은 작업을 정한다. 추론이 필요하면 해당 가이드와 로컬 모델 파일별 SHA-256을 계획 및 첫 실행 기록과 대조한다.

**완료 기준**은 색 변경을 저장하고 형태 변경 중 중단했을 때, 완료된 색 변경 PNG의 지문·수정 시각을 보존하고 나머지 작업만 각각 원본에서 생성하는 것이다. 가중치·토크나이저·설정이 바뀐 경우 해당 경로를 표시하고 추가 추론 전에 멈춰야 한다. 준비만 한 폴더는 `generate`, 이미 시작한 폴더는 `resume`을 안내한다. 모두 끝난 폴더는 모델 적재 없이 이미지 수와 저장 위치를 보고한다.

## 8. PNG 저장 직후 중단과 개별 이미지 손상 복구하기

| 재현할 상황 | 완료 기준 |
|---|---|
| PNG를 최종 경로로 옮긴 직후 성공 기록 전에 중단 | 해당 작업을 원본 가이드에서 다시 만들고 성공을 기록한다. |
| 성공 기록이 있는 `floor.png` 한 장이 누락되거나 손상 | 같은 장면·반복의 `floor` 한 건만 원본에서 다시 만든다. 다른 유효한 결과의 지문·수정 시각을 보존한다. |
| 작업이 남아 있는 상태에서 원본 가이드가 변경됨 | 영향을 받는 추론 전에 경로를 안내한다. 원본을 복원하면 그 가이드에서 남은 작업을 이어간다. |
| 복구가 끝난 실행을 다시 재개 | 추가 생성 0회이며 PNG 수와 저장 위치가 올바르다. |

## 9. 파일럿 정리와 정식 CLI 배포 검증

정식 CLI의 독립 편집과 7·8단계의 중단·복구를 확인한 뒤 아래 항목을 배포 마감 체크리스트로 사용한다.

- [ ] **설치 환경 고정.** `pyproject.toml`의 의존성 선언을 바탕으로 Linux·Python 3.12·CUDA 12.8에서 검증한 전체 패키지 버전과 PyTorch CUDA 빌드의 설치 경로를 `requirements/linux-py312-cu128.lock`에 기록한다. [참고 프로젝트의 설치 환경 관리](https://github.com/sirius-mhlee/vision-loop-boilerplate/blob/main/requirements/README.md)
- [ ] **실행 가능한 예제 배포.** 가림이 준비된 거실 가이드와 `scenarios.xlsx`를 `examples/living-room/`에 함께 둔다. 색·형태·환경·낮밤 지시를 독립된 행으로 적고 엑셀의 상대 경로로 가이드가 열리는지 확인한다.
- [ ] **파일럿 전용 파일 정리.** 예제를 옮긴 뒤 `scripts/pilot_a.py`, `scripts/pilot_abc.py`, `requirements/pilot.txt`와 Git이 추적하는 기존 `pilot/` 예제 파일을 배포본에서 정리한다. README의 실행 경로와 `.gitignore` 예외를 새 구조에 맞춘다. 개인 입력·모델·실행 결과는 로컬 작업 파일로 관리한다.
- [ ] **README 실습 정리.** 설치 → 로컬 모델 준비 → 예제 엑셀 확인 → `vgen prepare` → `vgen generate` → 중단 후 `vgen resume` 순서로 작성한다. 원본과 변형별 비교 이미지, RTX 5060 Laptop 8GB 실측값, 관찰한 한계와 복구 동작을 싣는다.
- [ ] **새 클론에서 인수 테스트.** 정리된 배포 후보를 새로 클론하고 빈 `.venv`에서 README만 따라 설치한다. 기본 설치만으로 `prepare`가 예제 계획을 저장해야 한다. 추론 패키지 설치와 `python -m pip check`, 모델 준비를 마친 뒤 네트워크를 끊는다. 예제의 독립 변형들을 생성하고 별도 실행을 중단했다가 `resume`으로 남은 편집만 완료하는지 확인한다.

같은 오프라인 환경에서 필수 모델 파일이 누락되면 원격 요청 없이 해당 경로를 안내해야 한다. 10개 장면 × 3개 편집 × 100회 대량 준비는 터미널과 `plan.json`의 작업 수가 모두 3,000이며 모델 호출이 0회일 때 통과한다.
