# 단계별 구현 계획

첫 결과물은 실제 가이드에서 이동식 장애물을 지운 PNG 한 장이다. 그다음 전선의 배치와 가림이 가능한지 확인하고, 검증한 모델 호출을 `vgen`에 연결한다. 엑셀 형식과 최종 CLI 사용 예시는 [프로젝트 README](../README.md)에 있다.

기본 순서는 1단계부터 9단계까지다. 가이드나 모델을 준비하는 데 시간이 걸리면 GPU 없이 검증할 수 있는 3 → 4 → 5단계를 먼저 진행할 수 있다. 6단계에서 2단계의 실제 모델 호출과 5단계의 실행 코드를 연결한다.

## 1. 가이드 한 장에서 빈 바닥 A 만들기

**준비물**은 로컬 FLUX.2 [klein] 4B 모델 폴더와 가로형 로봇청소기 사진 한 장이다. 바닥 줄눈, 앞쪽 책상 다리, 치울 수 있는 장애물이 함께 보이는 사진을 쓴다. README의 예시 경로는 `models/FLUX.2-klein-4B/`와 `pilot/guides/living01.jpg`다.

RTX 5060 Laptop GPU 8GB에서 로컬 Diffusers로 한글 지시 한 건을 실행한다. EXIF 방향을 적용하고 가이드의 화면비를 유지한다. 초기값은 4스텝과 `guidance_scale=1.0`이다. 메모리가 부족하면 CPU 오프로딩이나 화면비를 유지한 해상도 조정으로 다시 측정한다.

**완료 기준**은 `A.png`에서 장애물이 사라지고 원래의 낮은 시점, 줄눈, 책상 다리 위치가 유지되는 것이다. 성공한 실행의 입력·출력 크기, GPU와 총 VRAM, PyTorch·CUDA·Diffusers 버전, 정밀도, 오프로딩 방식, 최대 GPU 메모리(측정 지표와 MiB)를 남긴다. 모델 적재 시간과 한 장 생성 시간(추론 시작부터 PNG 저장까지)은 따로 잰다.

## 2. 같은 장면에 전선을 놓고 가운데만 가리기

같은 가이드·기준 시드·해상도로 A → B → C를 두 폴더에서 각각 실행한다. 첫 실행의 B에는 해당 폴더의 `A.png`만 넣는다. 두 번째 실행의 B에는 해당 폴더의 `A.png`와 실제 전선 참고 사진을 순서대로 넣는다. C의 입력은 언제나 같은 실행의 `B.png`다.

**완료 기준**은 두 실행의 PNG 세 장씩, 총 여섯 장을 확인하는 것이다. 두 경우 모두 B에서는 줄눈 옆 전선 한 가닥과 양끝이 보여야 한다. C에서는 같은 책상 다리가 그 자리에서 전선 가운데만 가리고 양끝은 보여야 한다. 참고 사진을 쓴 경우 전선의 색과 형태도 대조한다. 단계별 시간·메모리와 가이드·A·B·C 비교 결과를 실제 예시로 남긴다.

## 3. 사람이 작성한 엑셀 읽기

`장면`과 `편집` 시트를 읽고 사진 경로를 엑셀 폴더 기준으로 해석한다. `가이드 사진`과 `GUIDE`, `A의 결과`와 편집 ID `A`를 각각 같은 원본으로 해석한다. 요청 장애물의 `없음`과 빈칸, 선택적인 참고 사진을 구분한다.

**완료 기준**은 사용자가 정한 임의의 편집 ID로 슬리퍼 색만 바꾸는 한 줄짜리 편집도 읽고 원본 엑셀을 보존하는 것이다. 필수 셀 누락, 중복·예약 ID, 읽을 수 없는 사진은 시트·행·열과 해당 값으로 찾을 수 있어야 한다. 엑셀 자체가 없으면 찾던 경로와 필요한 두 시트를 안내한다.

## 4. `vgen prepare`로 확인할 계획 저장하기

`vgen` 진입점을 등록하고 장면·반복별로 부모 편집이 먼저 오도록 작업을 펼친다. `plan.json`에 최종 한글 프롬프트, 작업별 시드, 부모와 참고 사진, 입력 사진 해시, 출력 경로, 모델 경로와 생성 설정을 저장한다. 터미널에는 예상 장수와 저장 위치를 표시한다.

**완료 기준**은 GPU와 가중치 없이 2개 장면 × 3개 편집 × 2회에서 12개 작업, 10개 장면 × 3개 편집 × 1회에서 30개 작업을 계획하는 것이다. 엑셀 행이 C·A·B여도 실행 순서는 A → B → C이며, A에서 분기하는 B와 D는 같은 반복의 A 한 건을 공유한다. 잘못된 참조와 순환은 셀 위치로 안내한다. 생성 전 다시 준비할 때는 유효한 새 계획만 한 번에 교체하고, 검사가 실패하면 기존 계획을 보존한다.

## 5. 저장된 계획의 실행 순서와 파일 기록 검증하기

`plan.json`의 작업을 실행하는 코드를 만들고 테스트용 생성기를 연결한다. 실행 전 입력 사진의 해시를 대조하고, PNG는 임시 파일에서 최종 위치로 옮긴 뒤 `manifest.jsonl`에 작업 결과와 부모·출력 해시를 기록한다.

**완료 기준**은 준비 후 엑셀을 수정해도 저장된 프롬프트·시드·순서로 실행되는 것이다. 준비 후 사진이 바뀌면 그 사진을 사용하는 작업의 추론 전에 경로를 알린다. 한 장면의 부모가 실패하면 자식에 사유를 남기고 독립된 장면은 끝까지 처리한다. 테스트에서 실제로 호출한 작업과 생성 파일을 대조한다.

## 6. `vgen generate`로 실제 PNG 생성하기

2단계에서 검증한 FLUX 호출을 5단계의 실행 코드에 연결한다. `generate`는 준비된 실행 폴더를 받고, 첫 추론 전에 `run.json`에 계획 해시, 실제 버전, 사용한 가중치·토크나이저·설정 파일의 상대 경로와 SHA-256을 기록한다. 파이프라인은 로컬 폴더에서 실행당 한 번 적재한다.

**완료 기준**은 2단계의 두 조건을 `prepare`와 `generate`로 실행해 계획에 적힌 위치에 A·B·C를 저장하고, B의 입력 순서와 이미지 품질을 확인하는 것이다. 계획이 없는 폴더는 모델 적재 전에 `prepare` 사용법을 안내한다. 한 번 생성을 시작한 폴더의 계획은 고정한다.

## 7. `vgen resume`으로 완료된 A부터 재사용하기

계획 해시와 성공 기록, PNG의 상태·해시, 부모 해시를 읽어 남은 작업을 정한다. 추론할 작업이 있을 때만 로컬 모델 파일별 SHA-256을 첫 실행의 `run.json`과 대조한다.

**완료 기준**은 B 추론 중 중단한 실행에서 A의 해시와 수정 시각을 보존하고 B·C만 만드는 것이다. 가중치·토크나이저·설정을 각각 바꿔 보면 달라진 경로를 표시하고 추가 추론은 0회여야 한다. 원래 파일을 복원하면 B부터 이어진다. 준비만 한 폴더에서는 `generate`를, 시작한 폴더에서 다시 `generate`를 호출하면 `resume`을 안내한다. 이미 완료된 폴더는 모델을 적재하지 않고 이미지 수와 경로를 보고한다.

## 8. PNG 저장 직후 중단과 부모 이미지 손상 복구하기

테스트용 생성기로 중단 시점과 부모 이미지의 내용 변화를 재현한다. 복구 범위는 새로 호출한 작업 목록과 파일 해시로 확인한다.

| 재현할 상황 | 완료 기준 |
|---|---|
| B의 PNG를 최종 경로로 옮기고 성공 기록 직전에 중단 | 기존 A를 읽어 B를 다시 생성하고, 성공을 기록한 뒤 C를 만든다. |
| 성공한 A의 PNG가 누락되거나 손상 | A를 복구하고 그 내용 해시가 달라지면 이전 A를 사용한 자식을 의존 순서대로 다시 처리한다. 유효한 독립 장면의 파일과 수정 시각은 유지된다. |
| 복구를 끝내고 같은 폴더에서 다시 재개 | 추가 생성 0회이며 PNG 수와 저장 위치가 올바르다. |

## 9. 오프라인 실습과 README 마무리

패키지와 모델을 준비한 뒤 네트워크를 끊고 실제 `prepare → generate → 중단 후 resume`을 확인한다. 로컬 모델의 필수 파일이 빠졌을 때는 원격 요청 없이 해당 경로를 안내하는지 검사한다. 대량 준비는 10개 장면 × 3개 편집 × 100회로 시험한다.

**완료 기준**은 대량 준비 시 터미널의 예상 수와 `plan.json`의 개별 작업 수가 모두 3,000이고 모델 호출은 0회인 것이다. README에는 검증한 설치 조합, 세 명령의 실행 예시, 실제 가이드·A·B·C 비교와 참고 사진 유무별 측정값을 싣는다. 테스트용 생성기로 확인한 복구 동작과 실제 GPU에서 확인한 결과를 밝혀 둔다.
