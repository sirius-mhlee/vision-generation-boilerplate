# 단계별 구현 계획

`편집` 시트의 A~F열에 `번호`, `편집 ID`, `가이드 이미지`, `레퍼런스 이미지 1`, `레퍼런스 이미지 2`, `프롬프트`를 순서대로 적는다. 번호는 사람이 편집 건을 찾아보기 위한 값이다. 가이드는 편집할 원본이고, 두 레퍼런스는 각각 선택이다. 각 사진에서 배경, 물체 등 무엇을 참고할지는 프롬프트로 지정한다. 레퍼런스가 두 장인 행도 반복당 모델 호출 한 번으로 PNG 한 장을 만든다. [엑셀 형식과 CLI 사용 예시](../README.md#정식-cli-사용-예시)

1~9단계를 완료했다. 새 클론에서 기본 설치만으로 3,000건의 계획을 저장하고, 고정한 GPU 환경에서 예제 다섯 장을 오프라인으로 생성했다. 중단 후 남은 편집을 재개했고, 개별 PNG 복구는 8단계에서 검증했다. [생성 결과](../README.md#3-생성하고-결과-확인) · [재개 실측](../README.md#4-중단된-생성-이어가기) · [개별 PNG 복구](../README.md#png-한-장-복구하기)

## 1. 가이드 한 장에서 빈 바닥 A 만들기

**완료.** 로컬 모델 `models/FLUX.2-klein-4B/`와 로봇청소기 시점을 본뜬 합성 가이드 `examples/living-room/guides/living01.png`를 사용했다. `scripts/pilot_a.py`로 노란 양말을 지웠고, 같은 조건에서 두 번 생성한 PNG의 해시가 일치했다. [입력과 결과 비교](images/pilot-a-comparison.png)

RTX 5060 Laptop GPU 8GB에서 로컬 Diffusers로 한글 지시 한 건을 실행한다. EXIF 방향을 적용하고 가이드의 화면비를 유지한다. 초기값은 4스텝과 `guidance_scale=1.0`이다. 메모리가 부족하면 CPU 오프로딩이나 화면비를 유지한 해상도 조정으로 다시 측정한다.

**완료 기준**은 `A.png`에서 장애물이 사라지고 원래의 낮은 시점, 줄눈, 책상 다리 위치가 유지되는 것이다. 성공한 실행의 입력·출력 크기, GPU와 총 VRAM, PyTorch·CUDA·Diffusers 버전, 정밀도, 오프로딩 방식, 최대 GPU 메모리(측정 지표와 MiB)를 남긴다. 모델 적재 시간과 한 장 생성 시간(추론 시작부터 PNG 저장까지)은 따로 잰다.

## 2. 같은 가이드에서 편집 종류별 품질 확인하기

**실험 완료.** 색·형태·배경·조명을 비교할 때는 가운데가 나무 다리 뒤에 가려진 전선이 있는 `examples/living-room/guides/living01_cable_behind.png`를 공통 가이드로 사용했다. 양말 교체는 양말이 보이는 `examples/living-room/guides/living01.png`에서 시작했다. 각 지시를 해당 원본에 따로 적용하고 가이드 뒤에 지정한 레퍼런스를 번호순으로 보냈다. ## 3. 사람이 작성한 엑셀 읽기

**구현·검증 완료.** 프로젝트 루트에서 `.venv/bin/vgen workbook examples/living-room/scenarios.xlsx`를 실행하면 각 편집의 번호·ID, 실제 엑셀 행, 가이드·레퍼런스 경로가 표시된다. `vgen.workbook.read_workbook()`은 검증된 행 목록을 반환하며 같은 입력 양식을 쓰는 파이썬 코드에서 호출할 수 있다. 테스트는 `.venv/bin/python -m unittest discover -s tests -v`로 실행한다. [예제 엑셀](../examples/living-room/scenarios.xlsx) · [입력 검증 코드](../vgen/workbook.py)

원본 엑셀에서 `편집` 시트를 읽기 전용으로 연다. 번호·ID·가이드·프롬프트는 필수이며 두 레퍼런스 칸은 각각 선택이다. 번호는 1 이상의 정수이며 중간 번호를 건너뛰어도 된다. 이미지 경로는 엑셀 폴더 기준 PNG 상대 경로다. 예제 이미지와 생성 결과는 압축 레벨 0으로 저장한다. 완전히 빈 행을 건너뛰고 값이 있는 각 레퍼런스의 경로를 검사한다. 2번만 채운 행에서도 프롬프트의 ‘레퍼런스 2’가 그 사진을 가리키도록 번호를 보존한다.

**완료 기준**은 여섯 열 양식에서 레퍼런스가 없는 행, 1번만 또는 2번만 채운 행, 두 칸을 모두 채운 행을 읽는 것이다. 같은 가이드를 재사용하거나 다른 가이드를 지정할 수 있다. 열 제목·순서 오류, 잘못된 번호, 중복 ID, 필수 셀 누락, 읽을 수 없는 가이드·레퍼런스는 시트·행·열과 값으로 안내한다. 엑셀 자체가 없으면 찾던 경로와 필요한 시트 형식을 안내한다.

## 4. `vgen workbook`으로 입력 확인하고 `vgen prepare`로 작업 계획 저장하기

**구현·검증 완료.** 기본 패키지와 엑셀·PNG 의존성만 설치한 별도 가상환경에서 네트워크와 모델 파일 접근을 차단하고 두 명령을 실행했다. 예제 5행 × 1회는 5건, 앞 3행 × 2회는 6건, 같은 사진을 재사용한 30행 × 100회는 3,000건이었다. 입력 오류·쓰기 실패 시 기존 계획의 내용과 수정 시각을 보존하는 동작도 확인했다. [설치 설정](../pyproject.toml) · [계획 생성 코드](../vgen/prepare.py) · [검증 테스트](../tests/test_prepare.py)

`pyproject.toml`에 기본 의존성인 openpyxl·Pillow와 `vgen` 진입점을 선언했다. PyTorch·Diffusers 등 추론 의존성은 `gpu` 선택 설치에 모았다.

설치 후 `vgen workbook <엑셀 경로>`는 읽기 전용 검사 결과를 터미널에 표시한다. `vgen prepare`는 같은 `read_workbook()` 함수를 직접 호출해 검사를 수행하고 계획을 저장한다. 두 명령은 각각 독립적으로 실행할 수 있다. 이후 `generate`와 `resume`은 저장된 계획을 읽는다.

각 편집 행을 요청한 횟수만큼 반복한다. `plan.json`에 엑셀의 번호·편집 ID와 반복 번호, 가이드와 사용한 레퍼런스 각각의 번호·경로·SHA-256 및 전달 순서, 프롬프트 원문과 모델에 전달할 문장, 시드, 출력 경로를 저장한다. 모델에는 첫 이미지가 가이드이고 뒤의 각 이미지가 몇 번 레퍼런스인지 명시한다. 계획 형식 1의 시드는 `[기준 시드, 편집 ID, 반복 번호]`를 공백 없는 UTF-8 JSON으로 직렬화한 SHA-256의 상위 53비트다. 출력은 `images/r<반복 번호>/<편집 ID>.png`로 정하고 모델 경로와 생성 설정도 기록한다.

**완료 기준**은 GPU와 가중치 없이 `vgen workbook`으로 예제 5건을 확인하고, `vgen prepare`로 5행을 1회 반복하면 5건, 이 중 3행을 2회 반복하면 6건을 계획하는 것이다. 행마다 입력은 가이드부터 한 장, 두 장 또는 세 장이다. `evening_cable`의 입력 순서는 거실·저녁 방·전선이어야 한다. 엑셀의 번호나 행 순서를 바꿔도 같은 편집 ID와 반복 번호의 입력·시드·출력 경로는 같다. 생성 전 다시 준비할 때는 검사를 통과한 계획만 한 번에 교체한다.

## 5. 저장된 계획의 실행과 파일 기록 검증하기

**구현·검증 완료.** GPU 패키지가 없는 가상환경에 설치한 배포 패키지에서 예제 다섯 건을 테스트용 생성기로 실행했다. `add_cable`만 실패시키자 성공 PNG 네 장과 오류 한 줄을 포함한 기록 다섯 줄이 남았고, 그 뒤의 두 편집도 완료됐다. 엑셀을 수정하고 삭제한 후에도 두 번의 반복에서 계획의 입력 순서·프롬프트·시드를 사용했다. [실행 코드](../vgen/generate.py) · [실패와 동시 실행 테스트](../tests/test_generate.py)

모델 적재 전 입력 전체의 지문을 대조하고, 작업 직전에 다시 확인한 바이트를 추론에 전달한다. 각 PNG는 임시 파일에서 검사한 후 최종 위치로 옮긴다. 그 뒤 `manifest.jsonl`에 편집 번호·ID·반복·시드·입력 경로와 지문·출력 경로·성공 여부를 기록한다. 성공 시 출력 지문과 측정값, 실패 시 오류 원인을 남긴다.

**완료 기준**은 엑셀을 수정한 뒤에도 저장된 프롬프트·시드·입력 사진으로 실행되는 것이다. 준비 후 가이드 또는 레퍼런스가 바뀌면 해당 작업의 추론 전에 경로를 알린다. `add_cable`의 추론 실패를 재현해도 다른 행은 각각 자기 가이드와 지정한 레퍼런스로 계속 실행돼야 한다.

## 6. `vgen generate`로 실제 PNG 생성하기

**구현·검증 완료.** 4단계에 준비한 `runs/living01/plan.json`으로 RTX 5060 Laptop GPU에서 다섯 작업을 실행했다. 가이드만 쓰는 두 행, 레퍼런스 한 장을 쓰는 두 행, 두 장을 쓰는 한 행이 모두 1672×941 PNG로 저장됐다. PNG의 무압축 데이터와 작업별 SHA-256을 확인했다. 두 레퍼런스로 저녁 배경과 양말 교체가 함께 적용됐다. 짧은 색 지시에서는 전선 이외에 바닥 줄눈도 빨개졌다. [다섯 행의 비교 이미지와 시간·메모리](../README.md#3-생성하고-결과-확인)

파일럿의 EXIF 방향 보정·화면비 보존·추론 코드를 `vgen`으로 옮겼다. 실행당 한 번 로컬 모델을 적재하고 작업마다 가이드와 레퍼런스 0~2장을 계획 순서로 한 번에 전달한다. 이번 실행의 가중치·토크나이저·설정 파일 18개의 지문을 대조했고 IPv4·IPv6 연결 호출은 0회였다. [GPU 생성 코드](../vgen/flux.py) · [모델 파일 식별](../vgen/model_files.py)

첫 추론 전 `run.json`에 계획 지문, 사용한 버전, 가중치·토크나이저·설정 파일의 상대 경로와 SHA-256을 기록한다. **완료 기준**은 레퍼런스가 빈 행과 장애물·배경 사진을 넣은 행을 한 실행에서 처리해 계획대로 PNG를 저장하고, 각 결과를 2단계와 같은 기준으로 비교하는 것이다. 미준비 폴더는 모델 적재 전에 `prepare`를 안내하고, 생성을 시작하면 계획을 고정한다.

## 7. `vgen resume`으로 남은 작업 이어가기

**구현·검증 완료.** RTX 5060 Laptop GPU에서 색 편집을 저장하고 형태 편집 중 Ctrl+C를 보냈다. 같은 폴더를 재개하자 형태와 두 레퍼런스 편집 두 건만 실행됐다. 색 편집 PNG의 SHA-256과 나노초 단위 수정 시각, 최초 실행 기록과 계획의 지문은 일치했다. 다시 재개했을 때는 기존 세 장을 확인하고 추가 생성 0장으로 끝났다. [실행 예시](../README.md#4-중단된-생성-이어가기)

테스트에서는 남은 행의 입력이 바뀌거나 모델 가중치·토크나이저·설정이 교체·누락됐을 때 경로를 확인했다. 같은 폴더의 동시 재개, 실패한 반복만 재시도, 실행 기록의 마지막 줄을 쓰는 도중 중단된 경우도 검증했다. [재개 코드](../vgen/resume.py) · [검증 테스트](../tests/test_resume.py)

계획 지문, 작업별 성공 기록, PNG의 상태와 지문을 대조해 남은 작업을 정한다. 추론이 필요하면 해당 행의 가이드, 지정한 레퍼런스, 로컬 모델 파일별 SHA-256을 계획 및 첫 실행 기록과 대조한다.

**완료 기준**은 색 변경을 저장하고 형태 변경 중 중단했을 때, 완료된 색 변경 PNG의 지문·수정 시각을 보존하고 나머지 작업만 각각 원본에서 생성하는 것이다. 가중치·토크나이저·설정이 바뀐 경우 해당 경로를 표시하고 추가 추론 전에 멈춰야 한다. 준비만 한 폴더는 `generate`, 이미 시작한 폴더는 `resume`을 안내한다. 모두 끝난 폴더는 모델 적재 없이 이미지 수와 저장 위치를 보고한다.

## 8. PNG 저장 직후 중단과 개별 이미지 손상 복구하기

**구현·검증 완료.** RTX 5060 Laptop GPU에서 예제 다섯 건을 별도 폴더에 실행했다. 마지막 `evening_cable.png`가 최종 경로에 저장된 직후 성공 기록을 쓰기 전에 프로세스를 종료했다. 이 미기록 상태, 파일 누락, PNG가 40바이트로 잘린 상태에서 각각 같은 가이드와 저녁 방·전선 레퍼런스로 한 장만 다시 생성했다. 원래 `evening_cable.png`와 복구본의 SHA-256은 일치했다. 다른 네 장은 모든 시도에서 SHA-256과 나노초 단위 수정 시각이 같았다.

같은 크기의 다른 정상 PNG로 교체한 뒤에는 복구 중에도 같은 지점에서 한 번 더 종료했다. 이전 성공을 무효화하는 `repairing` 기록 덕분에 복구본이 원래 바이트와 같아도 다음 재개가 한 건을 다시 생성하고 성공을 기록했다. 두 번째 레퍼런스가 바뀌었을 때는 추론 전에 해당 경로가 표시됐고, 원본을 복원하자 재개됐다. 모두 복구한 폴더의 마지막 재개는 기존 다섯 장, 추가 생성 0장이었다. [사용법](../README.md#png-한-장-복구하기) · [반복별 복구와 실패 처리 테스트](../tests/test_recovery.py)

| 재현할 상황 | 완료 기준 |
|---|---|
| PNG를 최종 경로로 옮긴 직후 성공 기록 전에 중단 | 계획에 적힌 입력 사진으로 해당 작업을 다시 만들고 성공을 기록한다. |
| 성공 기록이 있는 `evening_cable.png` 한 장이 누락되거나 손상 | 해당 반복의 한 건만 가이드와 두 레퍼런스의 지문·순서를 대조해 다시 만든다. 다른 유효한 결과의 지문·수정 시각을 보존한다. |
| 남은 행이 참조하는 가이드 또는 레퍼런스가 변경됨 | 영향을 받는 추론 전에 경로를 안내한다. 원본을 복원하면 남은 작업을 이어간다. |
| 복구가 끝난 실행을 다시 재개 | 추가 생성 0회이며 PNG 수와 저장 위치가 올바르다. |

- [x] **설치 환경 고정.** Linux x86_64·Python 3.12.3에서 설치 도구와 추론 환경을 고정했다. PyPI와 PyTorch 공식 CUDA 12.8 인덱스에서 받은 휠로 새 환경을 설치했고, GPU 선택 설치의 직접·전이 의존성 57개를 설치 버전과 대조했다. `pip check`와 단위 테스트 44개가 통과했다. [설치 도구 버전](../requirements/bootstrap.lock) · [GPU 의존성과 인덱스](../requirements/linux-py312-cu128.lock)
